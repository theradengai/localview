# Markdown 格式回归验证

测试使用仓库自建的 [Markdown 样例](fixtures/markdown-format-matrix.md) 和相对路径图片，不依赖用户另一台电脑上的文件。

## 本次修复

- 阅读预览、分栏和打印保留普通文本换行；转换发生在解析后的文本节点，不改写 Markdown 文件或代码块。
- 编辑模式显示普通列表圆点、有序列表实际序号和嵌套层级；任务框不再同时显示多余的圆点。
- 补齐下划线式标题、显式换行和转义标点的实时显示；进入对应源码区域仍可看到原始标记。
- 未激活的表格单元格与阅读预览共用安全 Markdown 渲染；粗体、斜体、删除线、高亮和链接在表格中显示，激活后编辑原文。
- 模式切换保留同一个编辑器，避免撤销历史丢失；隐藏的编辑器不可编辑，切换文档仍重置文档状态。
- 对齐正文宽度和标题字号，长文本在预览中自动折行。

## 浏览器与原生 WebKit

Chromium 在实际 React 页面上执行三种模式与编辑流程。样例得到 6 个任务框、2 个已完成状态、4 个嵌套列表、7 个换行节点；代码内容保持原样。表格编辑只改变目标单元格，跨模式撤销/重做均恢复预期原文。

截图保存在 `output/playwright/markdown-split.png`、`markdown-edit.png`、`markdown-narrow.png`。浏览器的示例图片路由使用仓库内固定 SVG，不访问外部资源。

额外使用临时 AppKit/WKWebView 测试进程加载同一前端，确认换行、任务列表、预览一致性、原文保持、跨模式撤销、表格格式及格内编辑、图片和 HTML 转义均通过。脚本保存在 `output/playwright/verify-markdown-webkit.swift`，过程不操作剪贴板和用户文件。

这验证了本机 WebKit 的渲染与交互。真实文件保存的既有应用回归测试通过；本轮没有在另一台 Intel Mac 上运行安装包，也没有宣称已完成该硬件的端到端验收。

## 明确的边界

- `- [ ]文字` 缺少空格，或子项缩进过深时，仍按 GFM 解释；现在保留可读换行，不会猜测层级或自动改写文件。标准任务写作 `- [ ] 文字`，通常使用 2 个空格嵌套。
- 编辑模式正在输入的位置显示 Markdown 源码；阅读预览显示渲染结果。空白行和活动光标区域并不追求像素完全相同。
- 跨行选区的粗体、斜体、删除线等工具栏按钮仍沿用既有限制；单行操作已验证。本轮未更改此命令范围。
- 嵌套/不规则/超限表格沿用源码回退；原始 HTML 不作为富文本执行。
- 安装包仍为 `0.2.0-beta.1`、临时签名、未公证；使用新交付目录区分旧包。
